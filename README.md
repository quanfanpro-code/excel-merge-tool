## 1. 这个工具是干嘛的？

你有没有遇到过这种情况：

- 🏦 从银行下载了一堆流水文件，每个银行导出的格式都不一样
- 📂 一个文件夹里有十几个表格文件，想合并到一起但手动复制粘贴太累
- 😵 合并后发现金额不能求和、日期不能排序，格式乱七八糟

这个工具就是专门解决这些问题的！它会：

- 🔍 **自动找到表格在哪** —— 跳过文件开头的账户信息、打印说明等废话，直接定位到真正的表格数据
- 🧹 **智能清洗数据格式** —— 金额变成可以计算的数字，日期变成统一格式，清除看不见的乱码字符
- 🔗 **自动合并相同格式的文件** —— 表头一样的文件自动归到一组，一键合并
- 🛡️ **加密文件自动跳过** —— 遇到有密码的文件不会崩溃，直接跳过继续处理

## 2. 它能处理什么文件？

| 文件类型 | 后缀名 | 说明 |
|---------|--------|------|
| 🟢 新版表格 | `.xlsx` | 2007年以后的新格式，最常见 |
| 🟢 老版表格 | `.xls` | 2003年以前的老格式 |
| 🟢 文本表格 | `.csv` | 用逗号、分号或制表符分隔的文本文件 |

💡 **贴心功能**：有些银行导出的文件后缀名写错了（比如明明是新格式却写了老格式的后缀），程序会读取文件的真实内容来判断格式，**不会被后缀名骗到**！

## 3. 怎么安装？

### 第一步：确保你电脑上有 Python

如果你还没装 Python，去 [python.org](https://www.python.org/) 下载安装。安装的时候记得勾选「Add Python to PATH」。

### 第二步：安装需要的库

打开命令行（按 `Win + R`，输入 `cmd`，回车），然后输入：

```
pip install openpyxl xlrd customtkinter
```

> 📌 `openpyxl` 是处理新格式表格的库，`xlrd` 是处理老格式表格的库，`customtkinter` 是让界面好看的库。

### 第三步：运行程序

在命令行里进入工具所在的文件夹，然后输入：

```
python main.py
```

或者直接双击 `main.py` 文件也行。

## 4. 怎么使用？（手把手教程）

### 📌 第一步：选择文件

程序打开后，你会看到一个窗口。点击左上角的 **「选择数据源」** 按钮。

这时会弹出文件选择窗口。你有两种选择方式：

**方式一：选择单个文件**
- 如果你只选了一个文件，程序会检查这个文件所在的文件夹里有没有其他表格文件
- 如果文件夹里有多个表格文件，会弹窗问你：**要不要合并整个文件夹？**
  - 选「是」→ 合并文件夹里所有表格文件
  - 选「否」→ 只合并你选中的那一个文件

**方式二：选择多个文件**
- 按住 `Ctrl` 键，点选多个文件
- 选中的这些文件会被合并

### 📌 第二步：选择处理模式

在「模式」下拉菜单里选一个：

| 模式 | 说明 | 什么时候用 |
|------|------|-----------|
| 🎨 **完整模式（保留样式）** | 保留原来的字体、颜色、边框等样式 | 要打印或给别人看 |
| ⚡ **快速模式（无样式）** | 不要样式，只要数据，速度快很多 | 只看数据、做分析 |

### 📌 第三步：点击「开始合并」

点击窗口上方的 **「开始合并」** 按钮，然后等着就行！

程序会在下面的日志区域实时显示处理进度，告诉你每一步在干什么。

### 📌 第四步：查看结果

合并完成后，结果文件会自动保存在你选择的文件所在的文件夹里。

文件名格式：`文件夹名字_合并结果_20260608_153000.xlsx`

日志区域会显示处理结果摘要，包括：
- ✅ 成功处理了多少个文件
- 🔒 跳过了多少个加密文件
- ❌ 有多少个文件处理失败
- 📊 总共合并了多少行数据

## 6. 程序是怎么工作的？（运行逻辑）

整个处理过程分为 **三个阶段**，程序会依次执行：

### 🔍 阶段一：读取文件并检测表格区域

程序会逐个打开你选择的文件，做以下事情：

1. **判断文件真实格式**：读取文件头部的二进制数据，判断是新版表格、老版表格还是文本文件
2. **读取全部数据**：把文件内容一行一行读进来
3. **寻找表格位置**：文件里可能有很多"废话"（账户信息、打印说明等），程序需要找到真正的表格从哪一行开始
4. **识别表头**：对每一行进行打分，找到最像"表头"的那一行
5. **提取数据**：从表头下面开始，逐行判断是不是有效的数据行，直到表格结束

#### 🧠 表头是怎么找到的？

程序对每一行进行 **多因子综合评分**，得分最高的那行就是表头。评分考虑的因素包括：

| 评分因素 | 加分还是减分 | 说明 |
|---------|-------------|------|
| 非空格子多 | ➕ 加分 | 表头行通常每列都有文字 |
| 文字长度适中（2-10个字） | ➕ 加分 | 表头文字一般比较短 |
| 包含"日期""金额"等关键词 | ➕ 加分 | 表头经常有这类词 |
| 下面的行列数稳定 | ➕ 加分 | 数据行的列数应该和表头一致 |
| 下面有日期、金额等数据 | ➕ 加分 | 表头下面应该是数据 |
| 本身包含日期或金额 | ➖ 减分 | 说明这行可能是数据行，不是表头 |
| 包含"打印""小计"等词 | ➖ 减分 | 明显不是表头 |
| 整行文字完全一样 | ➖ 大幅减分 | 可能是合并单元格的大标题（如"科目辅助余额表"） |
| 包含"余额表""明细账" | ➖ 减分 | 这是报表大标题，不是列表头 |

最终得分最高的那行（且超过一定分数线），就被认为是表头。

#### 📏 数据行是怎么判断的？

找到表头后，程序从表头下一行开始，逐行判断：

- ✅ **是数据行**：非空格子够多、包含日期/金额/账号等特征
- ⏭️ **跳过但继续**：空行直接跳过；重复的表头、"小计/合计"行、页码行这类非空噪声行也会跳过
- ❌ **停止提取**：连续好几行「非空但又不是数据」的行，就认为表格结束了（空行不算在停止条件里）

#### 🏗️ 多行表头处理

有些银行的表头是两行甚至三行，比如：

```
第一行：|     借方      |     贷方      |
第二行：|  原币  |  本币  |  原币  |  本币  |
```

程序会自动检测这种情况，把多行表头合并成一行，用下划线连接：

```
借方_原币 | 借方_本币 | 贷方_原币 | 贷方_本币
```

### 📂 阶段二：按结构分组

程序会把所有成功读取的文件，按照表头内容进行分组。

- 表头相似的文件（相似度达到85%以上）会被分到同一组
- 不同格式的文件会被分到不同组

比如：
- 📁 **组1**（10个文件）：表头是 `交易日期|摘要|借方|贷方|余额`
- 📁 **组2**（5个文件）：表头是 `凭证号|本方账号|对方账号|交易时间`
- 📁 **组3**（2个文件）：表头是 `序号|交易时间|币种|收入|支出`

### 🔗 阶段三：合并数据

把同组的文件数据合并到一起：

1. **统一列名**：把所有文件的列名收集起来，去重后按顺序排列
2. **对齐数据**：每个文件的数据按照统一列名对齐（没有的列就留空）
3. **添加来源标记**：每行数据后面会加上"数据来源"列，标明这行来自哪个文件
4. **写入文件**：把合并后的数据写入新的表格文件

## 7. 高级设置详解

点击界面上的 **「▶ 高级设置」** 按钮，可以展开参数调整面板。

> 💡 **一般不需要调整这些参数！** 只有在默认效果不理想时才需要微调。

### 参数一览表

| 参数名称 | 默认值 | 可以调的范围 | 它是干嘛的 |
|---------|--------|-------------|-----------|
| 表头判定阈值 | 0.50 | 0.10 ~ 0.90 | 控制程序对"哪一行是表头"的判断严格程度 |
| 数据行判定阈值 | 0.50 | 0.10 ~ 0.90 | 控制程序对"哪一行是有效数据"的判断严格程度 |
| 连续失败次数 | 5 | 1 ~ 20 | 连续多少行「非空但不像数据」时，认为表格结束 |
| 连续空行数 | 3 | 1 ~ 10 | 已失效：v4.7 起空行不再中断采集，此参数暂不生效 |
| 最小表格行数 | 1 | 1 ~ 10 | 表格至少要有多少行数据才被认为是有效表格 |
| 列数允许波动 | 30% | 10% ~ 50% | 数据行的列数可以和表头差多少 |
| 分组相似度阈值 | 85% | 50% ~ 100% | 两个文件的表头相似度达到多少才合并 |

### 怎么调？看场景！

#### 🤔 场景一：表头识别不准

**问题**：程序把数据行当成了表头，或者找不到表头

**调整方法**：
- 表头被误判为数据行 → 把「表头判定阈值」**调高**（0.60 ~ 0.70）
- 提示"未找到可信表头" → 把「表头判定阈值」**调低**（0.30 ~ 0.40）

#### 🤔 场景二：合并后数据不对

**问题**：合并结果里有很多空行或"小计"行，或者数据行数比预期少

**调整方法**：
- 有多余行 → 把「数据行判定阈值」**调高**（0.60 ~ 0.80）
- 数据丢失 → 把「数据行判定阈值」**调低**（0.30 ~ 0.40）

#### 🤔 场景三：表格数据被截断

**问题**：合并结果的数据行数比预期少，有些数据没进来

> 💡 从 v4.7 起，数据中间的空行已经**不会再截断数据**了。如果仍遇到数据丢失，多半是「连续失败次数」太严格，被一些非空但不太像数据的行提前终止了。

**调整方法**：
- 把「连续失败次数」**调大**（8 ~ 15）

#### 🤔 场景四：同格式的文件没分到一组

**问题**：同一个银行的两个文件被分到了不同的组

**调整方法**：
- 把「分组相似度阈值」**调低**（70% ~ 75%）

> 🔄 点击面板里的 **「恢复默认」** 按钮，可以随时还原所有参数。

## 8. 数据标准化（自动清洗）

程序会 **自动** 对数据进行清洗，不需要你手动操作。它会根据表头关键词自动识别哪些列需要处理。

### 💰 金额清洗

程序会自动识别金额列（表头包含"金额"、"借方"、"贷方"、"余额"、"收入"、"支出"等词），然后：

| 清洗前 | 清洗后 | 说明 |
|--------|--------|------|
| `1,234.56` | `1234.56` | 去掉千分位逗号 |
| `￥1,234.56` | `1234.56` | 去掉人民币符号 |
| `(100.00)` | `-100.00` | 括号负数变负号 |
| `(￥100.00)` | `-100.00` | 带货币符号的括号负数同样支持 |
| `'1234.56` | `1234.56` | 去掉文本前缀 |

清洗后，金额列就是真正的数字了，可以直接求和、做数据透视表！

### 📅 日期清洗

程序会自动识别日期列（表头包含"日期"、"时间"、"交易日期"等词），然后：

| 清洗前 | 清洗后 |
|--------|--------|
| `20240101` | `2024-01-01` |
| `2024/1/1` | `2024-01-01` |
| `2024年1月1日` | `2024-01-01` |

清洗后，日期列格式统一，可以正确排序和筛选！

### 🧹 隐形字符清除

程序会自动清理文本中看不见的"幽灵字符"：
- 零宽字符（肉眼看不见但会影响匹配）
- 不间断空格（看起来像空格但不是普通空格）
- 前后多余空白

## 9. 多Sheet支持

有些表格文件里面不止一个页面（叫做"Sheet"），每个Sheet可能有不同的数据。

### 🤔 什么时候会用到？

当你选择的文件里有包含多个Sheet的文件时，程序会 **自动弹出一个选择对话框**，让你勾选要处理哪些Sheet。

### 📋 Sheet选择对话框说明

对话框里会按文件分组显示所有Sheet，每个Sheet前面有个勾选框：

- ✅ **勾选的Sheet**：里面的数据会被提取并合并
- ⬜ **没勾选的Sheet**：会被忽略

对话框底部有四个按钮：

| 按钮 | 功能 |
|------|------|
| **全部选择** | 勾选所有文件的所有Sheet |
| **全部取消** | 取消所有勾选 |
| **确认** | 按照你的选择开始处理 |
| **跳过（仅第一个Sheet）** | 忽略多Sheet，每个文件只读第一个Sheet |

每个文件分组旁边还有 **「全选」** 和 **「取消」** 按钮，可以单独控制某个文件的Sheet选择。

## 10. 性能说明

### ⚡ 快速模式

快速模式下，程序会在**不降低识别准确性的前提下**做以下优化：
- 完全跳过所有样式处理（字体、颜色、边框等）
- 只提取数据值
- 使用特殊的写入方式（Write-Only模式），写入速度提升3倍以上
- 内存占用大幅降低

> 💡 快速模式和完整模式的**识别结果完全一致**，区别只在于是否保留样式和写入方式不同。

### 🚀 内部性能优化（v4.0）

程序在内部做了多项性能优化，**两种模式都会受益**：

- 📁 **文件级复用**：同一个文件只打开一次，多个Sheet共享工作簿资源，不会重复初始化
- 🧠 **表头模板复用**：如果后续文件的表头与已识别文件完全一致，自动跳过重型表头识别，直接复用结果
- ⚡ **判型结果缓存**：日期、金额、账号等判断结果会被缓存，相同内容不会重复计算
- 🔍 **噪声行快速过滤**：分页标记、打印信息、小计行等噪声行会被快速识别并跳过，不进入完整评分
- 📊 **分段计时日志**：处理过程中会显示每个阶段的耗时，方便定位性能瓶颈

### 📦 大文件处理

对于大型文件，程序会使用 **按行读取** 方式处理 xlsx 文件：
- 使用 openpyxl 的 read_only 模式，逐行读取数据
- 避免构建完整的可编辑工作簿对象
- 降低内存占用

## 11. 常见问题

### ❓ 为什么我的文件识别失败了？

可能的原因：
1. 📄 文件里没有明显的表格结构（全是文字说明）
2. 🔍 表头太不明显，得分没到阈值（试试调低「表头判定阈值」）
3. 📊 表格数据太少，少于最小行数要求
4. 🔒 文件有密码保护

### ❓ 为什么合并后金额不能求和？

v3.0版本以后已经自动进行金额清洗了。如果还是不行，请检查原始数据是否包含特殊字符。

### ❓ 为什么日期格式不统一？

v3.0版本以后已经自动统一日期格式了。如果某些特殊格式未被识别，可能是比较罕见的格式，欢迎反馈。

### ❓ 可以同时处理不同银行的文件吗？

可以！但是只有 **表头相同的文件** 才会合并到一起。不同格式的文件会被分成不同组。

### ❓ 输出文件可以自定义名字吗？

目前文件名是自动生成的（文件夹名 + 合并结果 + 日期时间）。如果需要自定义，可以在程序运行完后手动重命名。

### ❓ 为什么有些文件没有被合并？

可能的原因：
1. 这些文件的表头和选中分组的不一样
2. 文件识别失败，没有提取到有效数据
3. 文件被跳过（加密或格式不支持）

## 12. 使用注意事项

### 🔄 数据标准化是自动的

金额和日期的清洗不需要你手动操作，程序会根据表头关键词自动识别并处理。

### 🚫 不做字段统一

不同银行的表格格式不一样，程序 **不会强行把它们合并**。比如：
- 甲银行的表头是"交易日期、摘要、借方、贷方、余额"
- 乙银行的表头是"记账日期、交易内容、收入、支出、账户余额"

这两家银行的文件不会合并到一起，因为表头不一样。

### 🛡️ 保守策略

宁可少收一点数据，也不会把账户信息误当成数据。如果某一行看起来模棱两可，程序会选择跳过。

### 📁 格式容错

即使文件的后缀名写错了，程序也能正确识别真实格式。

### 🧱 失败不中断

如果某个文件实在识别不出来，程序会记录失败原因，然后继续处理其他文件。

### 🔧 v4.7（2026年8月13日）—— 表头识别与数据完整性修复

**数据正确性修复（关键）：**

- 🐛 修复银行流水这类「数据中间夹着大量空行」的文件，合并后表头错乱、数据大量丢失的问题
  - 原问题一：表头识别按「哪一段数据最多」来猜表头所在段。文件数据多、被空行切成好几段时，会误把某段里的真实交易记录当成表头，导致整张表从头到尾错位

- 📌 说明：界面「高级设置」里的「连续空行数」参数自本版起不再影响识别（因为空行已不再中断采集），该滑块暂时保留、留待后续清理
