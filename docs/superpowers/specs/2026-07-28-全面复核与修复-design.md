## 1. 关键技术决策与方案对比

### 决策1：金额/日期清洗的接入点（核心）

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 方案A（推荐）| 在合并写入阶段，对每个文件的紧凑数据行按表头关键词识别金额列、日期列，仅对这两类列清洗后再写入输出文件 | 影响面最小；不改原始数据，保底数据完整；表头识别仍用原始值，不受污染 | 同一文件多 sheet 需各自清洗一次（已是 per-file 循环，成本可忽略） |
| 方案B | 在读取阶段就清洗 | 一次清洗多处用 | 会改坏表头识别输入（表头里"金额"二字不会被清洗，但日期型表头单元格可能被误清洗）；保底数据也被改，丢失原始信息 |

**推荐方案A。** 新增 `cleaning.py` 的 `apply_column_cleaning(header, data_rows)`：先用 `identify_amount_columns`/`identify_date_columns` 定位列，再对这两类列的每个单元格分别调用 `clean_amount_value`/`normalize_date_value`。在 `merging.py` 合并写入前调用。

### 决策2：列名重复时的对齐方式

当前 `align_data_to_columns` 用「列名->索引」字典，重复列名会互相覆盖。

**方案（唯一合理）：按出现顺序配对同名列。** 构建统一列侧「列名->可用位置队列」，文件侧也按列顺序消费同名位置。这样两个「金额」列分别对齐到统一列的两个「金额」位，不串列。

### 决策3：列数允许波动接入

`score_data_row` 当前列数比例判断是硬编码 0.7/0.5/0.3。改为：读取 `col_count_tolerance`，当 `col_ratio >= 1 - tolerance` 时给满分档，否则按比例分档。这样调高容差（如 50%）会让"列数差得多"的行也被算作有效数据行，调低（10%）则更严格。

### 决策4：looks_like_amount 收紧（保守）

当前任意能 `float()` 成功的串都算金额，导致短整数序号被误判。

**保守收紧：纯整数串（无小数点、无千分位、无货币符号、无括号）且长度 <=4 时，不认为是金额。** 典型金额至少有小数位或千分位或更长。账号由 `looks_like_account_number`（8-25位）单独处理，不受影响。补回归测试确认不破坏现有"序时账"等场景。

# 第二轮复核增补（同日，v4.5 → v4.6）

关联：需求文档「第二轮复核增补」章节（R2-1 ~ R2-10）。

## 7. 关键技术决策与方案对比（第二轮）

### 决策 R2-1：重复列名的统一列收集（核心，唯一需要权衡的决策）

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 方案A（推荐）| 统一列收集时，每个列名按「所有文件中的最大出现次数」重复保留。如文件1表头 `金额,金额,日期`、文件2 `金额,日期` → 统一列为 `金额,金额,日期`；文件2 的数据按序配对只占第一个金额位 | 与 v4.5「按出现顺序配对」决策衔接，真正启用配对逻辑；输出列名与原表一致；不丢数据 | 同组文件同名列数不一致时，少列文件的后序同名列位为空（这正是按序配对的本意） |
| 方案B | 收集时给重复列名改名（金额_2） | 实现最直接 | 输出列名与原始表头不一致，用户看到的表头被篡改；下游用列名求和时找不到原列名，不可接受 |

**推荐方案A。** 实现：先统计 `max_counts = {列名: 各文件最大出现次数}`，再按原遍历顺序追加列名，已加入次数达到 max_counts 才跳过。`align_data_to_columns` 的 deque 配对逻辑不用改。

### 决策 R2-1b：对齐计划预计算（性能顺带优化）

现状：`align_data_to_columns` 每行重建「列名→位置队列」，一万行重建一万次。
设计：新增 `build_align_plan(row_columns, unified_columns) -> List[Optional[int]]`，返回每个统一列对应数据行的固定索引；逐行对齐退化为列表推导。语义与 deque 按序配对完全等价（每行独立消费、顺序相同）。`align_data_to_columns` 保留为薄包装（兼容既有测试与调用语义），内部改用 plan；merging 两条写入路径在行循环外构建一次 plan。

### 决策 R2-2：带货币符号的括号负数（唯一合理修法）

括号正则由 `\(([\d,.]+)\)` 扩为 `\(([\d,.￥$€£¥]+)\)`：括号内允许货币符号，捕获后走原有货币剥离+逗号剥离逻辑。剥离后为空串时仍命中既有「返回原值」兜底，风险为零。

### 决策 R2-3：恢复默认真刷新（唯一合理修法）

`AdvancedSettingsPanel` 增加 `self._sliders[key]`、`self._entries[key]` 引用；`_reset` 时对每个滑块调 `set(默认值)`，对每个输入框删旧值插默认值；数值标签的刷新逻辑保持原样。

### 决策 R2-4：取消状态显式标记（唯一合理修法）

`merge_excel_files_with_callback` 取消返回值加 `'cancelled': True`；正常完成返回值加 `'cancelled': False`。`_on_merge_complete` 见到 `cancelled` 显示「已取消，未生成输出文件」，进度标签置「已取消」，不走完成分支。

### 决策 R2-5：表头模板去重（唯一合理修法）

追加模板前检查是否已存在 `raw_header` 与 `header_row` 均相同的模板，存在则跳过。比较用 list 等值，成本可忽略。

### 决策 R2-6：兜底表头拼接集合去重（一致性修复）

`merge_multi_row_header` 兜底路径把 prev_value 相邻去重改为 seen 集合去重，与 `get_header_path` 语义一致；顺序保持首次出现顺序，空值/None 跳过逻辑不变。

### 决策 R2-7 ~ R2-10：删除与文档同步（无争议）

- 删 `FileContext._data_wb` 死字段
- 更新 main.py / components.py / dialogs.py 模块 docstring 为实际结构（去掉「分组选择」「拖拽区域」字样，版本号 v4.6）
- `read_tsv_file`：编码读取成功即返回（空文件返回 `([], 0, 0)`），不再误报「无法识别编码」
